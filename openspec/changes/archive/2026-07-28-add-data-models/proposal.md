## Why

The skeleton has a runnable app and a health endpoint, but no database models, no migrations, and no data access layer. Before search, auth, or audit logic can be built, the four domain tables must exist in the database with proper schemas, enum types, indexes, and Alembic migrations.

## What Changes

- Add `app/db/base.py` with shared declarative `Base`, `app/db/session.py` with engine/session factory/`get_db` dependency
- Add four SQLAlchemy 2.0 models in `app/db/models.py`: `analytics_reports`, `investigator_entities`, `case_manager_cases`, `search_audit_log`
- UUID primary keys with `gen_random_uuid()`, native Postgres ENUMs for `type` (investigator_entities) and `status` (case_manager_cases), JSONB for `investigator_entities.data`
- One thin repository per table under `app/db/repositories/` (add/get/list)
- Alembic setup: `alembic.ini`, `alembic/env.py` wired to `Base.metadata` and `Settings.DATABASE_URL`, first autogenerated migration reviewed by hand
- Seed script inserting 10 rows per domain table
- TDD: round-trip test for each model against real Postgres
