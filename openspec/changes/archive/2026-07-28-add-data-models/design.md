## Context

The project skeleton includes a FastAPI app factory, health endpoint, config, and Docker Compose with Postgres 16. No database schema, models, or data access layer exists yet. The four domain tables are defined in PROJECT.md §6 and must be materialized.

## Goals / Non-Goals

**Goals:**
- Declarative `Base` and session wiring in `app/db/`
- Four SQLAlchemy 2.0 models matching PROJECT.md §6 exactly
- UUID PKs with `gen_random_uuid()`, native Postgres ENUMs, JSONB, timezone-aware timestamps
- One repository per table (add/get/list only — no search queries)
- Alembic setup with reviewed autogenerated migration
- Seed script with 10 rows per domain table
- Round-trip test (RED → GREEN) for each model

**Non-Goals:**
- No search logic, auth, audit service, or endpoints
- No repository update/delete methods (not needed yet)
- No test for seed script (ad-hoc, run manually)
- No Keycloak or JWT changes

## Decisions

1. **Single model file.** All four models in `app/db/models.py`. Keeps imports simple. They'll be refactored into per-app modules if they grow.

2. **Native Postgres ENUM via SQLAlchemy `Enum` with `create_type=False`.** Avoid letting SQLAlchemy auto-create the type in every migration. Types are created once in the initial migration; `create_type=False` ensures Alembic owns the lifecycle.

3. **`investigator_entities.data` uses `postgresql.JSONB` (not generic `JSON`).** The schema requires JSONB semantics (indexing, operators).

4. **Repositories are thin.** Each repo gets `add()`, `get()`, `list()` — no filtering, no search queries. Search strategies will build on these later.

5. **Alembic env.py uses `Settings().database_url`.** Reuses the existing config rather than duplicating the connection string.

6. **Test DB via existing Postgres container.** Tests assume `docker compose up -d` has been run. A fixture creates all tables before the test session and drops them after. Each test runs in a transaction that is rolled back.

## Risks / Trade-offs

- **[Low] ENUM creation order.** The migration must create ENUM types before the tables that reference them. Autogenerate usually gets this right, but the review must verify.
- **[Low] `gen_random_uuid()` requires `pgcrypto` or PG 13+.** Postgres 16 has `gen_random_uuid()` built in (since PG 13). No extension needed.
